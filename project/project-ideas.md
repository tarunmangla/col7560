
## Project 1: Foundation Model for Speed Test Learning Tasks
**Abstract**: Recent work on early termination of speed tests ([TurboTest](https://arxiv.org/pdf/2510.21141)) uses task-specific machine learning models (classifier and regressor) trained on labeled data to predict final throughput and decide when a test can be safely stopped. In this project, you need to investigate whether a foundation model pre-trained on large-scale unlabeled network measurement data can improve performance on this task. The model should first be trained using self-supervised objectives over network traces and then fine-tuned for early termination via regression or classification. You should compare the model accuracy, robustness, and data efficiency against the original TurboTest ML models to evaluate whether foundation-model pretraining provides measurable benefits in network measurement tasks. While the focus of the project is on early termination of speed tests, the insights gained from this investigation could have broader implications for applying foundation models to other network measurement and performance prediction tasks.

## Project 2: Augmenting UDP Speed Tests with Machine Learning
Traditional UDP-based speed tests use a two-phase design: (i) *a probing phase*, where packet trains are sent across a range of rates to induce transient congestion across a range of rates, and (ii) *an estimation phase*, where available bandwidth is inferred by comparing sender and receiver inter-packet gaps and detecting a “knee point” in queuing delay. These methods rely on fixed heuristic mappings to identify the knee point, making them highly sensitive to measurement noise from cross-traffic and hardware variability. As a result, bandwidth estimates can be unstable or inaccurate. This motivates replacing the static mapping with a data-driven parametric model for improved robustness.
Related Work: [Machine learning for measurement-based bandwidth estimation](https://www.sciencedirect.com/science/article/pii/S0140366419303457). 
Your goal will be to implement an ML-based bandwidth estimation method for [Assolo](https://ieeexplore.ieee.org/document/5076361/), a UDP-based bandwidth estimation technique. You can use Mininet to emulate a diversity of network conditions and generate training data for the ML model. The model should take as input features derived from the probing phase and output a bandwidth estimate. You will need to evaluate the accuracy and generalizability of your ML-based estimation with the default estimation of Assolo.

## Project 3: Machine Learning for Video Conferencing Performance Prediction and Anomaly Detection 
In this project, you will investigate how machine learning techniques can be used to characterize and predict the performance of video conferencing applications (e.g., Teams) from passively observed network traffic. Using Real-time Transport Protocol (RTP) header fields — including sequence numbers, timestamps, and payload type — extracted from captured campus traffic, you will derive ground-truth performance metrics such as frame rate, frame jitter, and video bitrate. Building on this ground truth, the project is divided into two parts. In the first part, you will develop a supervised learning technique in which flow-level features extracted from packet traces (primarily derived from IP/UDP headers) are used to predict the RTP-derived performance metrics. While supervised learning methods are theoretically more accurate, their deployment in real-world networks can be limited by the scarcity of labeled data. In the second part, therefore, you will apply unsupervised learning methods to identify poor-performance sessions. The intuition here is that networks typically perform well and poor performance is an anomaly, making anomaly detection a natural and promising approach. You will be provided access to one day of captured campus network traffic, which should contain a large number of video conferencing sessions. You will need to preprocess the data to extract relevant features and labels, and then apply machine learning techniques to build models for performance prediction and anomaly detection. Finally, you will evaluate the accuracy and robustness of your models using appropriate metrics — such as RMSE and R² for regression tasks, and precision, recall, and F1-score for classification and anomaly detection — and analyze the trade-offs between the two approaches.

## Project 4: VideoNOC -- A Video Conferencing Network Operations Center Dashboard
Video conferencing applications such as Microsoft Teams have become essential to daily campus operations, yet network operators have limited visibility into their performance. Traditional network monitoring focuses on link-level metrics like utilization and packet drops, which do not directly reflect the application-level experience of end users. Building an automated system that can passively infer video conferencing quality from network traffic and present actionable performance summaries to operators would be a valuable step toward more intelligent campus network management.

In this project, you will build VideoNOC — an end-to-end video conferencing performance monitoring system for campus networks. You will be provided access to one day of captured campus network traffic, which should contain a large number of video conferencing sessions. You will then build a machine learning model (either supervised or unsupervised) that infers video conferencing performance from flow-level features primarily derived from IP/UDP headers, without relying on RTP information at inference time. A supervised approach would train a regression or classification model using the RTP-derived metrics as labels, while an unsupervised approach would treat poor performance as an anomaly, leveraging the intuition that most sessions perform well under normal network conditions.

Finally, you will integrate your model into a simple front-end dashboard that presents a network operator with hourly video conferencing performance summaries — including metrics such as the number of active sessions, the fraction of sessions experiencing poor quality, and trends over time — demonstrating how your ML pipeline could be deployed as a practical network operations tool. Your implementation should emphasize the systems aspects of the problem, including efficient feature extraction, scalable processing of network traces, and the ability to support near real-time performance prediction and reporting.


## Project 5: Intrinsic Evaluation of Network Foundation Models
Network foundation models (NFMs) have emerged as a promising approach to building generalizable ML solutions for networking tasks. By leveraging self-supervised pretraining on large volumes of unlabeled traffic data, these models aim to learn rich representations that transfer well to downstream tasks such as traffic classification and anomaly detection. However, existing NFMs vary widely in their architectures and pretraining strategies — some operate on raw packet bytes, others on flow statistics, and still others on image-based representations of traffic — making it difficult to understand what knowledge each model actually acquires during pretraining and how architectural choices affect representational quality.


In this project, you will conduct an intrinsic evaluation of network foundation models, going beyond standard downstream task accuracy to analyze the quality of the learned representations themselves. You will begin by reproducing the evaluation framework from a recent study that proposes three complementary analysis techniques: Embedding Geometry Analysis, which quantifies how effectively models utilize the representation space (e.g., through anisotropy measurement); Metric Alignment Assessment, which measures whether learned embeddings correlate with domain-expert features such as flow duration, packet sizes, and TCP dynamics; and Causal Sensitivity Testing, which evaluates how embeddings respond to controlled perturbations in protocol fields and traffic context. However, rather than simply reproducing existing results, you will go a step further: you will select two of the four evaluated foundation models (you are welcome to try more) on a common pretraining dataset derived from the campus network traffic (will be provided to you), thereby controlling for differences in pretraining data and isolating the effect of architecture and pretraining task design on representational quality. You will then apply the full intrinsic evaluation framework to your retrained models and compare the results to those obtained with the original pretrained checkpoints.

## Project 6: Extrinsic Evaluation of Network Foundation Models
Existing Network Foundation Models (NFMs) follow fundamentally different philosophies. One approach, exemplified by NetFound, trains a domain-specific foundation model from scratch on raw network packet data, learning representations tailored to the structure and semantics of network traffic. An alternative approach, exemplified by NetLLM, repurposes pretrained large language models (LLMs) by adapting them to networking tasks through multimodal input encoding and task-specific fine-tuning, leveraging the general reasoning capabilities already embedded in the LLM. Whether domain-specific pretraining or LLM adaptation produces better representations for networking tasks remains an open and important question.
In this project, you will conduct a comparative evaluation of these two contrasting approaches to network foundation models. You will fine-tune both NetFound and NetLLM on two downstream networking tasks of your choice (e.g., traffic classification and quality of experience prediction), using the same datasets and evaluation methodology for a fair comparison. You will analyze how each model performs across the two tasks, how much labeled data each requires to achieve reasonable accuracy, and how sensitive each is to distribution shifts in the input traffic. Through this evaluation, you will discuss the trade-offs between the two paradigms — considering not only accuracy but also computational cost, data efficiency, and ease of adaptation — and reflect on what these findings suggest about the future direction of foundation models for computer networks.

## Project 7: EarlyFlow — Early Classification of Network Applications

Modern networks carry traffic from a wide range of applications — video conferencing, streaming, gaming, cloud storage, and more. Network operators often need to identify the application generating a flow in order to perform traffic engineering, enforce policies, or diagnose performance problems. However, traditional traffic classification methods typically rely on observing an entire flow or deep packet inspection, which may not be feasible for encrypted traffic or real-time operational use.

In this project, you will build EarlyFlow, a system that performs early classification of application traffic using only the first few packets of each network flow. You will be given packet traces containing flows from multiple application categories (e.g., video conferencing, streaming, web browsing, cloud services, and gaming). Your task is to design a machine learning model that predicts the application class using features derived from the initial packets of a flow, such as packet sizes, inter-arrival times, burst patterns, and directionality.
